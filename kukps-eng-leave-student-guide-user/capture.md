ปรับ `main.tex` เทียบกับโค้ด `apps/web` และ `apps/api` ณ commit `a1a66ff` แล้ว การตรวจครั้งนี้เป็นการเทียบโค้ดและภาพเดิม ไม่ใช่การทดสอบ workflow บนระบบจริงครบทุกบทบาท ภาพเดิมที่คู่มือเรียกใช้มีครบ 39 ไฟล์ แต่จำนวนไฟล์ครบไม่ได้ยืนยันว่าภาพตรงกับหน้าจอปัจจุบัน ภาพใหม่ที่ขอด้านล่างยังไม่ได้ capture

`CAPTURE-GUIDE.md` เป็นประวัติแผนเดิมวันที่ 9 ตุลาคม ไม่ใช้ข้อสรุปว่า “รายงานเป็น mock” หรือ “ภาพครบแล้ว” เป็นสถานะปัจจุบัน รายงานปัจจุบันใช้ `LiveReportProvider` โหลดข้อมูลจริงตามบัญชี ส่วนตัวปรับอนุมัติอัตโนมัติบนหน้าจอเลือกได้ 1–5 วัน

เก็บภาพใน `images/` ของคู่มือ ใช้ PNG และชื่อในตาราง ภาพหลายส่วนใช้ `-1`, `-2` ตามลำดับเลื่อนหน้า ห้ามแทนภาพรายละเอียดด้วยภาพรายการ หากหน้าจอแตกต่างกันตามบทบาทต้องถ่ายแยกบทบาท

## เตรียมก่อนถ่าย

1. ใช้ระบบทดสอบที่มีข้อมูลเหมาะสม และตรวจชื่อ บทบาท ภาคการศึกษา กับขอบเขตข้อมูลก่อนถ่าย
2. หากรัน Role Test ในเครื่อง ให้ใช้คำสั่งจาก root โปรเจกต์ `pnpm dev:role-test:api` และ `pnpm dev:role-test` แล้วเปิด `/role-test` โหมดนี้มีไว้พัฒนาระบบ ไม่ใช่ขั้นตอนเข้าใช้งานสำหรับผู้อ่านคู่มือ
3. Route ในตารางเป็น path ภายในเว็บ เติม base path ที่ใช้จริง เช่น `http://localhost:3000/kukps-eng-leave-student` เมื่อรันตามค่าปัจจุบัน ตรวจ `apps/web/next.config.ts` กับค่ารันจริงอีกครั้ง
4. `{id}` ของคำร้องใช้ ID ที่เปิดจากรายการของบัญชี ส่วน `{studentCode}` ใช้รหัสนิสิตในที่ปรึกษา และ `{subjectCode}` ใช้รหัสวิชาที่ผู้สอนเข้าถึงได้ ห้ามใช้ค่าตัวอย่างจนหน้าจอไม่พบข้อมูล
5. ใช้หน้าจอคอมพิวเตอร์ขนาดเดียวกัน เช่น 1440 × 900 หรือ 1920 × 1080 ที่ zoom 100% ภาพโทรศัพท์ใช้ viewport ประมาณ 390 × 844 และเห็นแถบล่าง ถ่ายกราฟหลังโหลดเสร็จและปิดเมนูที่บังข้อมูล
6. หากข้อมูลจริงไม่เหมาะเผยแพร่ ให้ใช้บัญชี/ข้อมูลทดสอบหรือปิดบังชื่อ รหัส เบอร์ ที่อยู่ และรายละเอียดหลักฐานอย่างสม่ำเสมอ หน้า Login ต้องไม่มี Token, URL query หรือข้อมูล session ที่ใช้งานได้
7. การเปิดรายละเอียดใบลาของผู้สอนอาจบันทึกสถานะอ่านแล้ว ให้เตรียมรายการสำหรับถ่ายก่อนเปิด หากถ่ายกล่องยืนยันให้กดยกเลิก การสร้าง/อนุมัติ/ลบข้อมูลเพื่อถ่ายควรทำในชุดข้อมูลทดสอบ

## ผล Capture ล่าสุดหลังเชื่อมต่อสำเร็จ

ถ่ายภาพผ่านเบราว์เซอร์จริงครบกลุ่มนิสิต ที่ปรึกษา ผู้สอน หัวหน้าภาค รองคณบดี และเจ้าหน้าที่แล้ว เก็บไฟล์ JPEG ใน `images/` พร้อม `manifest.json` ระบุ URL ของแต่ละภาพ ภาพเดิม PNG เก็บไว้ และ `main.tex` เปลี่ยนไปใช้ภาพใหม่ที่มีแล้ว

- รายงานทั้งหมดที่ถ่ายแสดงชุดข้อมูลวันที่ 16 ตุลาคม 2569 เวลา 11:19:28 ไม่ได้กด ETL เพื่อเปลี่ยนชุดข้อมูล
- ตั้งค่าอนุมัติอัตโนมัติถ่ายครบสามบทบาท โดยไม่ได้บันทึกเปลี่ยนค่า
- ถ่ายกล่องยืนยันอนุมัติและไม่อนุมัติจากคำร้องรองคณบดีเลข 26 แล้วกดยกเลิกทั้งสองกรณี ไม่เปลี่ยนผลคำร้อง
- ถ่ายหน้าจัดการคณะ/สาขาและฟอร์มเพิ่ม/แก้ไขโดยไม่บันทึกหรือลบข้อมูล
- ถ่ายแบบฟอร์มนิสิตพร้อมเลือกวิชาและปิดเวลาตามตาราง แต่ไม่ได้บันทึกคำร้องใหม่
- บัญชีที่ปรึกษาและหัวหน้าภาคไม่มีคำร้องรอ จึงยังใช้ภาพขั้นพิจารณาเดิม ไม่ใช้ภาพคำร้องเสร็จสิ้นแทนปุ่มอนุมัติ
- รายงานผู้บริหารมีข้อมูลที่ยังไม่ทราบภาควิชา/หลักสูตรตามคำเตือนบนหน้าจอ ไม่ใช่ภาพแสดงข้อมูลครบทุก mapping

ยังขาด: ภาพโทรศัพท์, รายงาน ADMIN ที่เข้าได้ตามสิทธิ์จริง, ตัวอย่างคำร้องไม่อนุมัติ/อนุมัติอัตโนมัติ, วันเรียนพิเศษตรงวันหยุด, สถานะรายงานโหลดผิดพลาด และภาพอนุมัติที่ปรึกษา/หัวหน้าภาคจากคำร้องที่ถึงขั้นจริง ภาพรายละเอียดคำร้องบางตัวมีช่องข้อมูลว่างหรือชื่อ Mock lecturer ตามข้อมูลทดสอบ จึงเก็บในชุด capture แต่ไม่ใช้แทนภาพที่ข้อมูลสมบูรณ์โดยอัตโนมัติ

ถ่ายเพิ่มเมนูโทรศัพท์ครบสามกลุ่มและตั้งค่าบุคลากรแล้ว รวมภาพชุดใหม่ 84 ไฟล์ ส่วนภาพรายละเอียดผู้สอน/รองคณบดีที่มีข้อมูลส่วนตัวว่าง และภาพ SEC ที่ยังโหลดไม่ครบ เก็บไว้ในชุด capture แต่คงภาพเดิมในคู่มือเพื่อรอภาพสมบูรณ์ รายงาน ADMIN และกรณีเฉพาะที่ไม่มีข้อมูลยังคงรอถ่าย
